リスタート機構
==============

本節では :math:`{\mathcal H}\Phi` のlegacyリスタート機構と
固有ベクトル入力を説明します。

``ReStart`` モード
------------------

``CalcMod`` 入力ファイルの ``ReStart`` はsolverの継続方法を指定します。

* ``0``: リスタートしない
* ``1``: リスタートデータを出力する
* ``2``: リスタートデータを読み込み、更新したデータを出力する
* ``3``: リスタートデータを読み込む

legacyファイルはsolverごとに異なります。

* 基底状態Lanczos法は ``##_recalcvec_rank_$$.dat`` と
  ``##_TMComponents.dat`` を使用します。後者にはMPIプロセス数とOpenMP
  スレッド数を記録します。不一致は拒否し、環境行を持たない旧形式は警告付きで
  読み込みます。
* LOBPCG（CG）、TPQ、cTPQは ``tmpvec_set&&_rank_$$.dat`` を使用します。
  このファイル名に ``CDataFileHead`` は付きません。
* 実時間発展では ``OutputEigenVec=1`` のとき
  ``##_eigenvec_&&_rank_$$.dat`` を出力します。ヘッダのstepは次に実行する
  stepを表します。

バイナリ構造の詳細は出力ファイル仕様を参照してください。これらの形式は
実行環境に依存します。

``InputEigenVec`` モード
------------------------

``InputEigenVec`` は保存済み固有ベクトルの入力であり、``ReStart`` とは別です。

* ``0``: 固有ベクトルを読み込まない
* ``1``: 固有ベクトルを読み込み、そのまま使用する
* ``2``: 固有ベクトルを読み込み、:math:`H` を1回作用させ、規格化してから
  物理量を評価する（legacy Lanczos入力経路）

固有ベクトルの入力は固有値solverの反復を再開しません。
``OutputEigenVec=1`` は結果の固有ベクトルファイルを出力します。

反復回数
--------

legacy LanczosおよびLOBPCGリスタートでは、``Lanczos_max`` は保存点からの
追加反復数です。TPQ/cTPQおよび実時間発展では総step数なので、保存stepより
大きな値を指定します。

MPIの要件
---------

各MPIプロセスが自分のrankファイルを読み込みます。legacyリスタートおよび
固有ベクトルファイルでは、保存時と同じMPIプロセス数が必須であり、プロセス数の
変更には対応していません。model、Hilbert空間の分割、必要な場合はOpenMP
スレッド数、および実行バイナリの環境も一致させてください。

legacy出力の制限
----------------

現在の実時間発展の継続では ``SS.dat`` と ``Norm.dat`` をwrite modeで
開き直すため、以前の時系列行を置き換えます。またlegacy TPQ/cTPQの
``tmpvec`` は ``global_1st_norm`` を保存しないため、継続後の
``Norm_rand`` の同列には0を出力します。

長時間計算を継続する前に、リスタートファイルと時系列出力を退避し、継続後に
保存量を確認してください。
