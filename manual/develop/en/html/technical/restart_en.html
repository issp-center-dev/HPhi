6.6. Restart and state import¶

HPhi has three independent mechanisms. ReStart continues a solver from its saved algorithmic state, subject to the legacy exceptions below. InputEigenVec=1 imports a state for CG evaluation or as the first state of a new TimeEvolution clock. CalcSpec 4/5 resumes the Lanczos spectrum sequence through TMComponents and recalcvec. Their contracts differ even where vector layouts coincide.

The v3 solver checkpoint and sector v1/v2 state formats were introduced after the code used for releases through v3.7.2. Those releases use legacy raw vectors for the CG/TPQ/TimeEvolution paths described here. Format version 3 is independent of the HPhi release version.

6.6.1. Solver continuation¶

ReStart has the following values in CalcMod: 0 disables continuation, 1 starts a new run and writes checkpoints, 2 reads and updates checkpoints, and 3 reads checkpoints without rewriting them. The v3 manifest and vector format is used by CG, mTPQ, cTPQ and TimeEvolution in raw and TransSym bases. The saved and current MPI process counts may differ. HPhi reads the saved contiguous global intervals and redistributes their intersections to the current ownership. Sector v3 continuation also permits metadata layout changes between replicated (0) and distributed (1). The global vector order remains unchanged even though rank ownership changes.

ReStart=3 does not make observable output read-only. Continuation recovers and appends time-series files. If no TE continuation checkpoint is selected, an explicit InputEigenVec=1/SpectrumVec can instead start an import, as described below; this can replace existing time-series files.

Lanczos_max is an absolute final bound for v3 continuation. CG resumes at the saved iteration label; TPQ/cTPQ and TimeEvolution resume at the saved next step. If the bound is below the saved CG iteration label, or at or below the saved TPQ/cTPQ/TimeEvolution next step, HPhi evaluates the restored state, does not add time-series rows, and does not rewrite a checkpoint. CG includes the iteration labeled Lanczos_max, whereas TPQ/cTPQ/TimeEvolution exclude that step. A terminal CG checkpoint is rechecked with the current LanczosEps. A stricter tolerance can resume iterations; an upper-limit no-op must not be described as currently converged.

CheckpointInterval controls periodic CG, mTPQ and cTPQ checkpoints. Zero means end-only. TimeEvolution uses OutputInterval for continuation checkpoints, and its time table must contain the saved next step. See the restart file specification.

6.6.2. Validation limits¶

v3 validates the saved state, basis and solver unit, but does not require the same Hamiltonian. Its Hamiltonian word is informational: raw checkpoints store zero; sector checkpoints contain a parsed-H digest. A hamiltonian_changed=no message does not verify the propagation history. For time-dependent sector TE input the message is unknown, since the saved step’s H and the current base H are not comparable as schedules. Use the same H and propagation settings for continuation; use state import for a new H or protocol.

Additional checks and limits are:

  • CG restores states, search directions, Ritz values and iteration labels. Hx and Hp are recomputed, but H identity is not checked.

  • mTPQ does not check H or LargeValue. cTPQ checks its saved imaginary-time increment against the current 1/LargeValue, but not H or ExpandCoef. cTPQ with InvTemp rejects ReStart=2/3.

  • TE checks the saved boundary time and whether the table covers the saved next step. It does not compare earlier or later H/time rows or the Taylor order. Table/sector TE saves time[next_step-1]; raw Laser TE saves Tinit + next_step*TimeSlice. A matching boundary alone is not a matching protocol.

  • TPQ sample identity comes from the saved state and set label. Initial RNG settings and parallel counts describe how a fresh state was generated; changing the rank count for continuation does not regenerate that state.

6.6.3. State import¶

v3 and sector v1/v2 state import validates the model, basis identity, sector and phase, payload length, norm and digest. Source method, state, step, time and solver scalars are provenance; they do not resume the source solver. CG evaluates an imported state. TimeEvolution starts at step zero on its current time grid. v3 imports are redistributed automatically when the saved and current process counts differ. Sector v3 and old sector v1/v2 imports also permit metadata layout 0/1 changes. For v1/v2, HPhi verifies the payload checksum using the saved partition before redistribution and uses the partition-independent sector digest to validate the basis set. The basis builder’s canonical representative-state sort fixes its global order, so an equal set has the same order. The output-file reference gives the required copy procedure.

InputEigenVec=1 in CG evaluates the imported state; it does not run CG iterations from that state. Import does not require the source H to match the current H. The current H must still be valid in the selected sector.

Raw CG and raw TE OutputEigenVec and cTPQ InvTemp eigenvector output still use legacy raw layout. Thus ordinary raw CG-to-TE import uses legacy raw files, not the v3 solver manifest. This import remains supported, but its model/basis identity and payload checksum cannot be verified from that format.

Without a selected TE continuation checkpoint, a v3 or sector v1/v2 SpectrumVec starts at step zero even with ReStart=2/3. HPhi warns before replacing the SS, Norm, Flct and aggregate Green time series. To start an intentional new protocol, use a separate output directory and ReStart=0/1. A legacy raw SpectrumVec behaves differently: ReStart=2/3 uses its stored next step, whereas ReStart=0/1 imports it at step zero. Legacy raw TE has no saved clock to compare.

6.6.4. Changing the MPI process count¶

Keep every source-rank file, including a file for an empty owner. For v3 continuation, copy the manifest and every vector file named by it, then run with the desired process count; no extra parameter is needed. v3 continuation uses the count in each manifest row and ignores RestartSourceRanks. This also permits an interrupted TPQ/cTPQ migration to resume when some samples are v3 files written by the new process count and other samples are legacy files: the parameter applies only to those remaining legacy samples. It can be removed after all samples have been republished as v3.

For v3 or sector v1/v2 state import, copy every source file under the import prefix and run with the desired process count. Their headers provide the source count. RestartSourceRanks is optional for state import and acts only as an additional equality check.

For legacy raw import or continuation, copy every saved per-rank file and add RestartSourceRanks=<saved process count> to ModPara before changing the process count. HPhi never guesses this value from file names, because a missing empty trailing rank would otherwise be indistinguishable from a smaller complete file set.

6.6.5. Legacy and spectrum behavior¶

Legacy raw tmpvec_set*_rank_*.dat remains readable by CG and TPQ/cTPQ. Because this format stores neither its source rank count nor identity words, rank-changing reads require RestartSourceRanks. Keep every saved rank file, including an empty trailing rank; HPhi checks all native headers, file lengths, steps and the global dimension before redistribution, but cannot validate model or sector identity from the files. Legacy CG keeps its historical additional-iteration meaning: only the states are restored, search directions are zeroed, and Ritz values are recomputed with the current H. Iteration labels restart at one and the old Lanczos_Step prefix is not recovered. The input states are assumed to already be normalized and orthogonal; the legacy reader does not reestablish these properties. This is warm-start-like behavior, not v3 X/P continuation or a general warm-start interface. Legacy TPQ/cTPQ and raw TimeEvolution recover output rows below their validated next step when possible. Old sector v1/v2 files are state-import formats, not solver continuation checkpoints.

Legacy mTPQ cannot restore the initial norm and reports zero for it. Legacy cTPQ reconstructs beta as (step-1)/LargeValue, which assumes that LargeValue has not changed. Neither path verifies H identity.

Ground-state Lanczos and CalcSpec 4/5 retain their existing TMComponents/recalcvec behavior and iteration meaning. They do not use the v3 solver manifest.

6.6.6. Output recovery¶

Before appending, HPhi validates every required checkpoint, removes complete rows at or after the recovery boundary, drops an incomplete final line, and rejects malformed interior rows. A missing history file is created and only new rows can then be written; a missing prefix cannot be reconstructed. Per-set files and CG/TimeEvolution histories reproduce uninterrupted row order. Shared TPQ aggregate files follow execution order, so compare them by sorted (set, step, observable) keys when several sets resume.

The CalcTimer.dat rows Restart write (7100), Restart read (7110) and Restart recover outputs (7120) measure v3 publication, continuation vector loading, and time-series validation/rewrite respectively. They are instrumentation totals, not a controlled storage benchmark.
