v3 solver restart files¶

CG, mTPQ, cTPQ and TimeEvolution use these files for ReStart continuation. The saved and current MPI process counts may differ. HPhi reconstructs the global vector from the saved contiguous intervals and reads their intersections with the current ownership. A TransSym v3 continuation may also change metadata layout 0/1 between replicated and distributed without changing global vector order. Independently published TPQ sets may therefore have different saved rank counts and layouts; all rank files within one set must agree. Old sector v1/v2 state imports also permit rank-count and layout changes.

Names, units and manifest¶

Vectors are named <CDataFileHead>_restart_set<k>_comp<c>_gen<g>_rank_<r>.dat. k is a CG state, TPQ sample, or zero for TimeEvolution; component 0 is the state and CG component 1 is its search direction. The generation is 0 or 1. The publication unit is all states and both components for CG, one sample for TPQ/cTPQ, and set 0 for TimeEvolution.

<CDataFileHead>_restart_manifest.dat is the sole pointer to published data:

hphi_restart_manifest 1
method <CG|TPQ|cTPQ|TimeEvolution>
basis <raw|sector>
set <k> ranks <P> gen <g> step <STEP> ncomp <1|2>

CG rows have one rank count, generation and step. TPQ rows are independent. ReStart=3 never modifies these files. A new ReStart=1 publication replaces unrelated old rows. Writers create every .part file, rename the complete unit, then atomically publish the manifest. Only after publication are superseded files removed. The manifest therefore never names a partial unit.

Each vector contains 40 little-endian unsigned 64-bit words, followed by LOCAL_DIM pairs of IEEE binary64 real and imaginary values. Vector index zero is omitted.

Comparison and digests¶

Across ranks of one set/component, only RANK, OFFSET and LOCAL_DIM differ. CG state and direction components may additionally differ in COMPONENT and data digests. CG states may differ in STATE, data digests and SCALAR_A; all share step, flags, set count, generation and rank count. TPQ samples may have independent state, step, data/scalars and manifest rows, but their basis identity and method agree.

The data digest hashes each global index and the exact real/imaginary bits, then reduces both XOR and unsigned sum across ranks. Sector order digests hash the global index, representative, orbit size and stabilizer size. The pair of reductions detects corruption and ordering changes without depending on the partition.

Rank redistribution¶

v3 and sector v1/v2 files carry their saved rank count, offsets and local dimensions. Keep every file from rank 0 through the saved count minus one, including files with zero payload. HPhi validates the complete saved set and then reads each overlap between a saved interval and the current interval. RestartSourceRanks is not required for these self-describing formats. v3 continuation ignores it and uses the count in each manifest row. A v3 or sector v1/v2 state import treats a positive value as an optional equality check against the saved count.

For sector v1/v2, HPhi first reproduces the old partition-dependent DATA checksum from the saved files. Only after that check succeeds is the payload redistributed. The partition-independent sector digest verifies the basis set; the canonical representative-state sort fixes its global order. Source and destination layouts may be either 0 or 1, but every source file in one checkpoint must declare the same valid layout.

Legacy raw files have only a native 12-byte STEP/local-dimension header. They do not record the saved rank count or identity. A rank-changing legacy read therefore requires RestartSourceRanks=<saved count>. HPhi requires all declared files, verifies their headers, lengths, common step and summed dimension, and reports that only dimensions—not model or sector identity—were checked.

Recovery and legacy selection¶

For every required set, HPhi first uses a manifest row. A missing or corrupt referenced v3 file is fatal and never falls back to legacy data. Without a row, complete legacy files are validated and used. ReStart=2 starts a new set only if neither source exists; ReStart=3 reports an error. v1/v2 sector files are import-only. Legacy CG restarts additional iterations with labels starting at one and do not recover the old CG history prefix. A legacy rank change requires RestartSourceRanks as described above.

History recovery preserves rows before STEP, removes later rows and an incomplete EOF fragment, and rejects corrupt interior text. Terminal CG keeps its already emitted terminal row only when it still satisfies the current convergence test. Aggregate TPQ rows are appended in execution order; compare multiple resumed sets after sorting by (set, step, observable).

Using a v3 vector as an imported state¶

Read the selected set and generation from the manifest. Copy every ..._restart_set<k>_comp0_gen<g>_rank_<r>.dat file to the existing import name, <SpectrumVec>_rank_<r>.dat for TimeEvolution or <CDataFileHead>_eigenvec_<state>_rank_<r>.dat for CG. Keep all source rank files and set RestartSourceRanks to that count when specifying it. This parameter is optional for v3, but must match the saved count when present. The current rank count and, for a sector, layout may differ. Import starts a new solver clock; it is not continuation.
