# ELPA FullDiag フェーズ3 — 物理量計算の分散化（ExpecMode）設計文書

- 日付: 2026-07-11（v1）
- 対象: FullDiag の固有ベクトルからの物理量計算（`src/phys.c` と `expec_*` 群）
- 前提: フェーズ1（ELPAソルバー、`Solver` キーワード）とフェーズ2（ハミルトニアン
  分散生成）が完了していること（設計: `2026-07-10-elpa-fulldiag-design.md`）
- ステータス: 設計（実装前）

## 1. 背景と目的

フェーズ2完了時点で、FullDiag の O(N²) 複製メモリは解消済み（`Z_vec` は
2Dブロックサイクリック分散、作業ベクトルは O(N)）。残る制約は
**物理量計算の直列化**である:

- 固有状態を 1 本ずつ rank 0 の `v0` に集約（合計 O(N²) の対 rank 0 通信、
  `GetEigenVectorBlock` × N 回の集団転送）
- `expec_*` の実質計算は rank 0 のデータのみで進む（他ランクはゼロを持って
  `SumMPI` 集団和に参加するだけ）。全 N 状態を処理する FullDiag では
  N 状態 × 状態あたり O(N×ペア数) の仕事が 1 ランクに載る

### 目標

- **主用途: 有限温度 FullDiag（全状態の熱平均）、N ~ 10⁴–10⁵**
- 物理量計算の実時間を ~P 倍に短縮し、状態ごとの集団転送を排除する
- 2 方式をユーザー選択可能にする:
  - **Mode 1（状態タスク並列）**: 既存 `expec_*` コードを無改造で再利用する汎用方式
  - **Mode 2（トレースカーネル）**: エネルギー系・一体GF・二体GFの
    状態バッチ専用カーネル（B未対応量は自動的に Mode 1 で処理）

### 非スコープ

- FullDiag 以外の計算タイプ（Lanczos/LOBCG/TPQ の期待値は既存のサイト分割
  並列のまま）
- ヒルベルト空間のサイト分割モードへの載せ替え（検討したが不採用 — §7 代替案）
- スペクトル計算（フェーズ1で `Solver 1/3` 分散モードとの併用を起動時拒否済み）

## 2. ユーザーインターフェース

`calcmod.def` に新キーワード **`ExpecMode`**（int 型、既定値 0）を追加する。

| 値 | 動作 |
|---|---|
| 0 | 従来どおり（rank 0 直列。既定） |
| 1 | 状態タスク並列（各ランクが担当状態の物理量を独立計算） |
| 2 | トレースカーネル（エネルギー系・一体GF・二体GF）。対象外の物理量はその状態処理のみ Mode 1 相当で実行 |

### 起動時検証（`readdef.c`、既存の Solver 検証群に追加）

- `ExpecMode` の値域チェック（0–2）。
- `ExpecMode >= 1` かつ `iCalcType != FullDiag` → エラー。
- `ExpecMode >= 1` かつ `iSolver ∉ {SOLVER_SCALAPACK, SOLVER_ELPA}` → エラー
  （分散 `Z_vec` を持つソルバーが前提。**`Solver 1` でも有効**）。
- `ExpecMode >= 1` かつ `nproc == 1` → rank 0 に INFO を表示して
  `ExpecMode 0` で実行（エラーにしない: 入力ファイルをランク数に依存させない）。
- 表示は rank 0 のみ（既存慣例）。

## 3. アーキテクチャ

### 共通基盤: 状態パネル再分散

対角化直後に 1 回だけ実行する:

```
RedistBlockCyclicToStatePanel():
  Z_vec [N×N, 2D block-cyclic, nblk=ElpaBlockSize]
    → (pzgemr2d ×1)
  StatePanel [N × ncols_local, 連続カラムメジャー]
    rank r が状態（=列）の連続ブロック [r*NC+1, min((r+1)*NC, N)] を
    「完全な固有ベクトルとして」所有。NC = ceil(N/P)。
  直後に Z_vec を解放。
```

- 実装・所有権計算・ゼロ所有ランク処理・集団同期エラー処理は、フェーズ2の
  `RedistPanelToBlockCyclic`（逆向きの変換）と同じ規約・同じファイル
  （`matrixscalapack.c`）に置く。
- メモリ: パネルは O(N²/P)（`Z_vec` と同じ）。変換中のみ両者が併存する
  一時ピーク 2×16N²/P（フェーズ2の再分散時ピークと同水準。N=10⁵, P=32 で
  10 GB/ランク）。変換後は O(N²/P) 1 枚。
- **ブロック（連続）配分を選ぶ理由**: 状態あたりの計算量は一様なので
  ラウンドロビンとの負荷差はなく、状態順の出力集約が「ランク順の連結」で
  済む（§5 出力）。
- `Solver 1`（pzheev）経路も `Z_vec`/`descZ_vec` を生成するため同じ基盤に乗る。
  ただし Solver 1 の `descZ_vec` は `GetBlockSize` ベースの nblk であることに
  注意（ディスクリプタから読むので実装上は透過）。

### ローカルモードフック（Mode 1 の要）

グローバルフラグ `iExpecLocal`（`wrapperMPI.c` / `FileIO.c` が参照）を導入する。
ON の間:

1. `SumMPI_dc` / `SumMPI_d` / `SumMPI_li` 等のリダクション関数は
   **入力値をそのまま返す**（`MPI_COMM_SELF` での集団和と等価。
   `MPI_Comm` の配管を追加せずに済む）。
2. `fopenMPI` は rank 0 ゲートを外し、**呼び出しランクでローカルに**開く。

これにより既存の `expec_*` 関数群（内部で `SumMPI` と `childfopenMPI` を使う）
が**無改造で**各ランク独立に正しく動く。ON/OFF は必ず対で行い、エラー経路でも
OFF に復元してから集団エラー処理に入る（ハング防止）。実装時に expec 経路から
呼ばれる wrapperMPI 関数を全列挙し、リダクション系すべてにフックを入れる。

### Mode 1: 状態タスク並列ドライバ

新ファイル `src/phys_distributed.c` の `phys_stateparallel()`:

```
for (自ランク所有の各状態 n):
  StatePanel の列 n → v0 にローカルコピー（1-based 詰めは既存 phys.c と同じ）
  iExpecLocal = ON
    expec_energy_flct → expec_cisajs → expec_cisajscktaltdc
    → expec_nbodyg → expec_anomalousg → expec_totalspin
  iExpecLocal = OFF
  X->Phys.all_*[n] に記録（自分の区間）
ループ後:
  all_* 配列を MPI_Gatherv で rank 0 へ（ブロック所有なので連続区間の gather）
  集約形式 Green ファイル: 各ランクのパーシャルファイルを rank 0 が
  ランク順に連結（＝状態順）
```

- 状態別ファイル（`*_eigen%d` 系）は各ランクが直接書く（ファイル名が状態番号で
  一意なので衝突しない）。
- **`expec_totalspin`（`<S²>`）が分散モードで復活する**（現行は
  use_scalapack 時にスキップして 0 を出力している）。Mode 0 の分散実行は
  従来どおりスキップ（挙動不変）、Mode 1/2 では計算する。
- rank 0 の進捗表示（`i=... Energy=...` 行）: 各ランクが自状態分をバッファし、
  all_* 集約後に rank 0 が状態順で出力する（従来と同じ見た目を維持）。

### Mode 2: トレースカーネル

新ファイル `src/expec_trace.c`。対象: `expec_energy_flct` 相当（エネルギー・
対角量）、一体GF（`cisajs`）、二体GF（`cisajscktaltdc`）。構造は
**「演算子ごとに基底写像を 1 回前計算 → 所有全状態をストリーミング」**:

1. **写像前計算**: 演算子 Ô（例: c†ᵢσ cⱼσ）について、各基底状態 k に対する
   行き先 k′ と符号/位相 s_k を O(N) の配列として 1 回だけ構築する。
   ビット演算は makeHam / mltply*Core の既存の要素関数群（`child_*` 系）を
   写像抽出に再利用する（新しい物理ロジックは書かない）。
2. **状態ストリーミング**: `g_n = Σ_k conj(z_n[k′]) · s_k · z_n[k]` を
   所有状態 n について密ループで評価（メモリバンド幅律速）。
   汎用 expec コードが状態×要素ごとに払うテーブル参照・分岐コストを
   N/P 状態分だけ償却するのが Mode 1 に対する利点。
3. **エネルギー系**: `<H>` は固有値をそのまま採用。対角量（ダブロン、num、Sz）
   は対角写像の自明なストリーミング。分散 `<H²>-<H>²` の検査は同じ写像機構で
   H の全項を適用して任意実行（既定 ON、従来出力との互換のため）。
4. **二体GF**: 一体写像の合成（k →(cₖcₗ...)→ k″）で同構造。スピン組合せ・
   ペア数のループが外側に増えるだけで、内側の状態ストリーミングは共通。
5. **フォールバック**: NBodyG / AnomalousG など B 対象外の物理量が入力で
   要求されている場合、その量だけ Mode 1 の経路（ローカルモード + 既存 expec）で
   処理する。ユーザーから見て Mode 2 = 「速い経路が使える量は速く、
   他は Mode 1 と同じ」。
6. 出力は Mode 1 と同じ機構（状態別はローカル書き、集約はランク順連結）。

### phys.c の分岐

`phys()` の冒頭で `ExpecMode >= 1 && use_scalapack` なら
`phys_stateparallel()`（Mode 2 はその中でカーネル選択）へ委譲し、
従来経路は一切変更しない。状態パネルへの再分散は委譲直前に実行する
（Mode 0 では従来の `GetEigenVectorBlock` 経路のまま）。

## 4. エラー処理

- readdef 起動時検証（§2）で不整合を全て事前に弾く。
- `RedistBlockCyclicToStatePanel` はフェーズ2 と同じ集団同期パターン
  （malloc 失敗の Allreduce 同期、所有権整合ガード、失敗時は全ランク同時に -1）。
- `iExpecLocal` の set/reset は構造的に対にする。expec 中のエラーは
  ローカルモードを解除してから集団的に伝播（全ランク `MPI_Allreduce(MIN)` で
  失敗共有 → `exitMPI`）。
- パーシャルファイル連結は rank 0 のみが行い、欠損パーシャル（あるランクの
  書き込み失敗）は連結時に検出してエラー終了。

## 5. 出力互換性

- 状態別ファイル（`zvo_cisajs_eigen%d.dat` 等）: ファイル単位で従来と同一内容。
- 集約形式（`green_output_format` 機能）: rank 0 がランク順（＝状態順）に
  パーシャルを連結し、従来と同一のファイルを生成する。
- `zvo_phys_*.dat`（サマリテーブル）と標準出力の `i=... Energy=...` 行:
  all_* 集約後に rank 0 が状態順で出力（従来と同一）。
- Mode 1/2 で `<S²>` が計算されるようになる点だけが従来（分散時 0 埋め）との
  差分。ドキュメントに明記する。

## 6. テスト計画

- **モード等価性（主軸）**: 同一入力で `ExpecMode 0/1/2` の全出力
  （phys テーブル、状態別・集約 Green ファイル）を比較。エネルギーは一致、
  GF は 1e-8。対象: Hubbard 鎖（一体・二体GF）と SpinGC Gamma≠0。
  np = 2/3/4 の複数構成（ゼロ所有状態ランクを含む構成も）。
- 状態パネル再分散の単体テスト（`elpa_redist_check` の姉妹版:
  `GetEigenVectorBlock` による列回収結果とパネル内容の全要素比較）。
- Mode 2 カーネル単体: ランダムベクトルに対して演算子写像の結果を
  汎用 expec（Mode 1 経路）と突き合わせ。
- 既定動作の回帰: `ExpecMode 0`（既定）で全既存テスト無変更 PASS。
- clavius 実機 + **ベンチマークゲート**: N=4900 全状態の一体+二体GF 実時間を
  Mode 0 / 1 / 2 で比較（有限温度ワークロードの代理）。目標: Mode 1 で ~P 倍、
  Mode 2 は Mode 1 以上。
- 手動検証プロトコル（`test/manual/elpa_gpu_check.md`）にフェーズ3 項目を追加。

## 7. 検討した代替案（不採用）

- **真の PBLAS トレース形式（ブロックサイクリックのまま pzgemm で
  diag(Z†OZ)）**: 演算子は疎な基底置換なので密 BLAS3 の恩恵がなく、
  ブロックサイクリック上の置換適用は通信を伴い複雑になるだけ。状態パネル上なら
  演算子適用が通信ゼロになるため不採用。
- **サイト分割レイアウトへの載せ替え**（Lanczos/TPQ の MPI 並列 expec を再利用）:
  FullDiag は起動時に非分割モードを選んでおり（`iFlgScaLAPACK` ゲート）、
  `list_1` 等の分割簿記との整合コストが最も高い。不採用。
- **ラウンドロビン状態配分**: 負荷分散上の利点がなく（状態あたり仕事一様）、
  出力の状態順集約が複雑になるため、ブロック配分を採用。

## 8. 実装分割とマージ計画

1. **フェーズ3a**: `ExpecMode` キーワード + 状態パネル再分散 + ローカルモード
   フック + Mode 1 + モード等価性テスト。単体で完結した価値（~P 倍の実時間短縮、
   `<S²>` 復活）。
2. **フェーズ3b**: Mode 2 カーネル（エネルギー系 → 一体GF → 二体GF の順に
   サブステップ化）+ カーネル単体テスト + ベンチマーク。
3. 各フェーズで AI レビュー + clavius 検証（フェーズ1/2 と同じ運用）。
