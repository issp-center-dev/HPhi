# ELPA FullDiag フェーズ3 — 物理量計算の分散化（ExpecMode）設計文書

- 日付: 2026-07-11（v5: 白紙ホリスティックレビュー反映）
- 対象: FullDiag の固有ベクトルからの物理量計算（`src/phys.c` と `expec_*` 群）
- 前提: フェーズ1（ELPAソルバー、`Solver` キーワード）とフェーズ2（ハミルトニアン
  分散生成）が完了していること（設計: `2026-07-10-elpa-fulldiag-design.md`）
- ステータス: 設計（実装前）

## 1. 背景と目的

フェーズ2完了時点で、FullDiag の O(N²) 複製メモリは解消済み（`Z_vec` は
2Dブロックサイクリック分散、作業ベクトルは O(N)）。残る制約は
**物理量計算の直列化**である:

- 固有状態を 1 本ずつ rank 0 の `v0` に集約（合計 O(N²) の対 rank 0 通信、
  `GetEigenVectorBlock` × N 回の集団転送）
- `expec_*` の実質計算は rank 0 のデータのみで進む（他ランクはゼロを持って
  `SumMPI` 集団和に参加するだけ）。全 N 状態を処理する FullDiag では
  N 状態 × 状態あたり O(N×ペア数) の仕事が 1 ランクに載る

### 目標

- **主用途: 有限温度 FullDiag（全状態の熱平均）、N ~ 10⁴–10⁵**
- 物理量計算の実時間を ~P 倍に短縮し、状態ごとの集団転送を排除する
- 2 方式をユーザー選択可能にする:
  - **Mode 1（状態タスク並列）**: 既存 `expec_*` コードを無改造で再利用する汎用方式
  - **Mode 2（トレースカーネル）**: エネルギー系・一体GF・二体GFの
    状態バッチ専用カーネル（B未対応量は自動的に Mode 1 で処理）

### 非スコープ

- FullDiag 以外の計算タイプ（Lanczos/LOBCG/TPQ の期待値は既存のサイト分割
  並列のまま）
- ヒルベルト空間のサイト分割モードへの載せ替え（検討したが不採用 — §7 代替案）
- スペクトル計算（フェーズ1で `Solver 1/3` 分散モードとの併用を起動時拒否済み）

## 2. ユーザーインターフェース

`calcmod.def` に新キーワード **`ExpecMode`**（int 型、既定値 0）を追加する。

| 値 | 動作 |
|---|---|
| 0 | 従来どおり（rank 0 直列。既定） |
| 1 | 状態タスク並列（各ランクが担当状態の物理量を独立計算） |
| 2 | トレースカーネル（エネルギー系・一体GF・二体GF、**モデル別に検証済みのものだけ有効化**）。対象外の物理量・未検証モデルはその状態処理のみ Mode 1 相当で実行 |

**保証（specとユーザードキュメントに明記）**: `ExpecMode` は速度のみを変え、
計算結果は丸め誤差の範囲で 0/1/2 すべて一致する（総和順序が変わるため
bit 一致ではない点もドキュメントに明記し、バグ報告を予防する）。
利用指針: フェーズ3b 以降は通常 2 を推奨。1 は相互検証用と 3a 段階の
インターフェース。3a のみのビルドで `ExpecMode 2` が指定された場合は
INFO を表示して 1 として動作する。Mode 2 実行時は、どの物理量がカーネルで
処理されどれがフォールバックかを rank 0 が開始時に 1 度 INFO 表示する
（NBodyG 主体の入力で速度差が出ない理由をユーザーが分かるように）。

### 起動時検証（`readdef.c`、既存の Solver 検証群に追加）

- `ExpecMode` の値域チェック（0–2）。
- `ExpecMode >= 1` かつ `iCalcType != FullDiag` → エラー。
- `ExpecMode >= 1` かつ `iSolver ∉ {SOLVER_SCALAPACK, SOLVER_ELPA}` → エラー
  （分散 `Z_vec` を持つソルバーが前提。**`Solver 1` でも有効**）。
- `ExpecMode >= 1` かつ `nproc == 1` → rank 0 に INFO（`stdoutMPI`、文言:
  "ExpecMode reverts to 0 for a single process (results are identical)."）を
  表示して `ExpecMode 0` で実行。フェーズ1 の「黙ったフォールバック禁止」
  原則の例外だが、正当: nproc==1 の Mode 1 は Mode 0 と結果も性能も同一
  （GPU の場合と違い、フォールバックで失うものがない）。入力ファイルを
  ランク数に依存させないための意図的な設計。
- `Solver 1` は nproc==1 のとき分散 `Z_vec` を作らない（ZHEEVall/L_vec に
  フォールバック）が、上記 nproc==1 規則が先に適用されるため矛盾しない
  （`_SCALAPACK` ビルド要件は Solver 1 自体の検証が担う）。
- `AnomalousG` 等が既存の検証で分散 FullDiag を拒否している場合、その拒否は
  ExpecMode に関係なくそのまま有効（ExpecMode は既存の量別サポート範囲を
  広げも狭めもしない — 3a の監査で現状の拒否条件を確認し等価性テストの
  対象範囲に反映する）。
- FullDiag に隣接する他オプションの扱い: `OutputEigenVec`/`InputEigenVec` は
  FullDiag 経路では従来から未使用（影響なし）。`OutputHam`/`InputHam` は
  フェーズ2 のゲートがそのまま適用（ExpecMode と独立）。スペクトル計算は
  フェーズ1 のゲートで分散モード自体が拒否済み。これ以外に phys() 経由の
  出力オプションが増えた場合は phys_stateparallel での扱いを明示すること。
- 表示は rank 0 のみ（既存慣例）。

## 3. アーキテクチャ

### 共通基盤: 状態パネル再分散

対角化直後に 1 回だけ実行する:

```
RedistBlockCyclicToStatePanel():
  Z_vec [N×N, 2D block-cyclic, nblk=ElpaBlockSize]
    → (pzgemr2d ×1)
  StatePanel [N × ncols_local, 連続カラムメジャー]
    rank r が状態（=列）の連続ブロック [r*NC+1, min((r+1)*NC, N)] を
    「完全な固有ベクトルとして」所有。NC = ceil(N/P)。
  直後に Z_vec を解放。
```

- 実装・所有権計算・ゼロ所有ランク処理・集団同期エラー処理は、フェーズ2の
  `RedistPanelToBlockCyclic`（逆向きの変換）と同じ規約・同じファイル
  （`matrixscalapack.c`）に置く。
- メモリ: パネルは O(N²/P)（`Z_vec` と同じ）。変換中のみ両者が併存する
  一時ピーク 2×16N²/P（フェーズ2の再分散時ピークと同水準。N=10⁵, P=32 で
  10 GB/ランク）。変換後は O(N²/P) 1 枚。
- **ブロック（連続）配分を選ぶ理由**: 状態あたりの計算量は一様なので
  ラウンドロビンとの負荷差はなく、状態順の出力集約が「ランク順の連結」で
  済む（§5 出力）。
- `Solver 1`（pzheev）経路も `Z_vec`/`descZ_vec` を生成するため同じ基盤に乗る。
  ただし Solver 1 の `descZ_vec` は `GetBlockSize` ベースの nblk であることに
  注意（ディスクリプタから読むので実装上は透過）。
- 宛先ディスクリプタ仕様（フェーズ2 の 1D パネルと同形）: 1×P グリッド
  （'R', 全ランク）、`M=N, N=N, MB=N, NB=NC, RSRC=CSRC=0, LLD=N`。
  正確な所有式（フェーズ2 と同一）: `NC = ceil(N/P)`;
  `first_state(r) = r*NC + 1`（1-based）;
  `ncols_local(r) = max(0, min((r+1)*NC, N) - r*NC)`。
  ディスクリプタの NB は全ランク共通で NC（最終ブロックが欠けるのは
  ScaLAPACK のブロックサイクリック規約どおりで、numroc_ と一致）。
  ゼロ所有ランクは 1 要素のダミーバッファ＋有効ディスクリプタで集団参加
  （この LOCc=0 + 1要素バッファ + LLD=N パターンは、フェーズ2 の逆向き
  再分散で clavius 実機 np=50（ゼロ所有ランクあり）にて `pzgemr2d` が
  バッファに触れないことを実測検証済み）。
  `pzgemr2d` はユーザー可視の追加ワークを要求しない（内部バッファは
  実装依存だが O(局所ブロック) — フェーズ2 実測でも問題なし）。
  グリッドは変換後に `blacs_gridexit_` で解放。

### ローカルモードフック（Mode 1 の要）

スコープ付き API `ExpecLocalEnter()` / `ExpecLocalLeave()`（`wrapperMPI.c`）で
制御されるフラグ `iExpecLocal` を導入する（生のフラグ書き換えは禁止。
入れ子は不可としアサート。`phys()` 出口で OFF であることをデバッグアサート。
プロセスグローバルなフラグとする — HPhi はスレッド化された expec を持たず、
FullDiag の phys は 1 回だけ呼ばれるため十分。将来スレッド化する場合は
スレッドローカル化が必要な旨をヘッダに注記）。

**ExpecLocal 許可呼び出しマトリクス（インターフェース契約）**: expec 経路から
到達し得る wrapperMPI / FileIO / green_output の各関数について、ローカルモード
時の挙動を実装前に確定し、ヘッダのコメントとして残す。方針:

| 関数群 | ローカルモード時の挙動 |
|---|---|
| `SumMPI_dc/d/li/i` 等リダクション全種 | **入力をそのまま返す**（MPI を呼ばない → 内部の `exitMPI` にも到達しない） |
| `BcastMPI_*` / `MaxMPI_*` / `BarrierMPI` / `NormMPI_*` 等 | expec 経路での使用を実装時に全列挙。使用があればリダクションと同様に無通信化、無ければ「ローカルモード中の呼び出しをデバッグアサートで禁止」 |
| `fopenMPI`（→`childfopenMPI`） | rank 0 ゲートを外し呼び出しランクでローカルに開く（失敗は NULL 返却 → 呼び出し側の既存エラー処理に乗る） |
| `stdoutMPI` への fprintf | rank 0 のみ表示のまま（他ランクの進捗はバッファし後で集約 — §Mode 1）。expec 内の警告類は rank 0 以外で失われるが、致命的エラーは戻り値経由で伝播するため許容 |
| `exitMPI` | **ローカルモード中は呼んではならない**（片ランクの exit は他ランクをハングさせる）。expec の戻り値を収集して後述のランデブーで集団処理 |
| **生の `MPI_*` 呼び出し**（wrapperMPI を経由しないもの） | **ローカルモード中は到達禁止**。既知の該当箇所: `nbody_correlation.c` / `anomalous_pair.c` の「partner/origin ≠ myrank」分岐（`MPI_Sendrecv` + 直接 `exitMPI`）。これはサイト分割モード用の分岐で、複製 FullDiag モード（iFlgScaLAPACK=1、MPI 分離サイトなし）では partner==myrank が常に成立し**到達不能のはず**だが、3a のコールインベントリタスクで partner_rank 系関数を監査して証明し、さらに**防御ガード**を入れる: ローカルモード中に partner≠myrank 分岐へ入ろうとしたら生 MPI を呼ばずに rc=-1 でその状態の処理を失敗させる（数箇所の分岐先頭に `if (iExpecLocal) return エラー` を追加） |
| green_output 系（集約ファイル） | 専用のパーシャル出力モード（下記）に切り替え |

将来の退行防止として、`expec_*.c` / `nbody_correlation` / `anomalous_pair` から
マトリクス外の wrapperMPI 関数**および生の `MPI_` 呼び出し・直接 `exitMPI`**が
（防御ガードなしで）現れたら失敗するチェックスクリプトをテストに加える。
検査対象ファイル集合と許可リスト（wrapperMPI.c 自身、コメント・include 行の
除外）を明示し、単純 grep でなくトークン認識（コメント除去後のマッチ）の
軽量スクリプトとする。**マトリクスの確定（expec 到達コールグラフ全体 —
`child_*`/`GC_child_*`/モデル別ヘルパ経由の間接呼び出しを含む — の機械的
インベントリ生成と各関数の挙動決定）は、フェーズ3a の最初の実装タスクとして
Mode 1 コーディング前に完了させる**（直接 grep だけで済ませない）。

**集約 Green ファイルのパーシャル出力（must-fix 対応）**: `fopenMPI` の
ローカル化だけでは、集約形式（`green_output_format`）の**全ランクが同名
ファイルに追記して競合**する。これは fopenMPI ではなく green_output 層で
解決する: `GreenOutputSetPartialSuffix(rank)` を導入し、ローカルモード中は
全集約種別（一体・二体・NBodyG・AnomalousG・その他全 kind）のファイル名に
`.part<rank>` を付す。パーシャルには最終形式の行（eigen index プレフィクス
込み）をそのまま書き、rank 0 の連結は純粋なバイト結合とする。

**連結の成否判定はファイルサイズで推測しない**（ゼロ所有ランクや、演算子
選択によっては所有状態があっても正当に空のパーシャルが存在するため）。
代わりに**ランク別マニフェスト**を使う: 各ランクは kind ごとに
{attempted, opened, open_error, rows, closed_ok, part_path, final_path} の
ステータスレコードを持ち、全パーシャルをクローズした後、ループ後の
単一ランデブーで rank 0 へ gather する。状態の意味を明確に定める:
attempted=真 かつ rows=0 かつ open_error=偽 は「正当な空出力」
（part ファイルが物理的に存在しなくてもよい）; attempted=真 かつ
open_error=真 のみが失敗。part_path と final_path は別フィールドで持ち、
公開名の導出をランク側の記録に依存させない（`.part<rank>` 名での誤公開を
構造的に防ぐ）。rank 0 の連結は**当該実行のマニフェストレコードのみ**を
読み（ファイル名でのディレクトリ走査はしない）、過去の失敗実行が残した
古い `.part*` を誤って取り込まない。各ランクは最初の書き込み前に自分の
part_path を unlink してから開く。rank 0 は
(a) 全ランクの成功が揃った場合のみ連結・公開・パーシャル削除を行い
（グローバル rc が失敗なら連結せず、パーシャルは診断用に残す）、
(b) マニフェストに「attempted」とあるのにファイルが開けない場合のみエラー、
(c) ゼロ所有ランク・正当に空のパーシャルは空として正常に連結する。
連結と最終ファイル初期化の順序: `GreenOutputInitializeAggregateFiles()` に
よる最終名ファイルの初期化（トランケート）は **rank 0 が公開時（連結直前）
に 1 回だけ**行う（現行 phys.c の「状態ループ前」から移動）。各ランクの
part ファイル初期化（unlink→open）とは名前空間が分離しているため競合しない。
連結対象の kind とファイル名の完全なリストはマニフェスト自体から得る
（NBodyG/AnomalousG などオプション出力やモデル依存の命名を推測しない）。
状態別ファイル（`*_eigen%d`）はこの機構の対象外
（ファイル名が一意なので直接書く）。

### Mode 1: 状態タスク並列ドライバ

新ファイル `src/phys_distributed.c` の `phys_stateparallel()`:

```
rc_local = 0
ExpecLocalEnter(); GreenOutputSetPartialSuffix(myrank)
for (自ランク所有の各状態 n):            # rc_local != 0 になったら残りをスキップ
  X->Phys.eigen_num = n                   # 状態別ファイル名・行プレフィクスの整合
  StatePanel の列 n → v0 にローカルコピー（1-based 詰めは既存 phys.c と同じ）
  rc = expec_energy_flct → expec_cisajs → expec_cisajscktaltdc
       → expec_nbodyg → expec_anomalousg → expec_totalspin
  失敗時: rc_local = -1（exitMPI は呼ばない — ローカルモード中は禁止）
  X->Phys.all_*[n] に記録（自分の区間）
ExpecLocalLeave()
MPI_Allreduce(MIN) で rc_local を全ランク共有   # 唯一のランデブー点
  → どこかで失敗していれば全ランク同時に exitMPI
all_* 配列を MPI_Gatherv で rank 0 へ（ブロック所有なので連続区間の gather）
集約形式 Green ファイル: rank 0 がパーシャルをランク順（＝状態順）に連結・削除
```

- 状態別ファイル（`*_eigen%d` 系）は各ランクが直接書く（`eigen_num` を毎状態
  設定するのでファイル名・内容とも従来と同一）。
- rank 0 の進捗表示（`i=... Energy=...` 行）: 文字列ではなく**数値フィールドを
  集約**し（all_* 配列そのもの）、rank 0 が集約後に既存フォーマット文字列で
  再レンダリングして状態順に出力する（フォーマットの一元管理・テスト容易性）。**表示フォーマットはシリアル版
  （S2 列あり、`phys.c` 現行の非分散側）に統一**する（下記 `<S²>` の扱い参照）。
- **`<S²>`/`Sz` の統一（レビュー must-fix 対応）**: 現行の分散 Mode 0 は
  `S²` と `Sz` の両方をゼロ埋めし、標準出力も S2 列なしの別形式になっている
  （`phys.c:165-208`）。本フェーズで **Mode 0（分散）でも rank 0 に集約済みの
  `v0` に対して同じ ExpecLocal フックで `expec_totalspin` を実行**し、
  S²/Sz/表示形式を非分散時と統一する。これにより「ExpecMode は速度のみを
  変える」保証が 0/1/2 で厳密に成立する。従来の分散 Mode 0 出力
  （S²=Sz=0 埋め）からの意図的な挙動修正（バグ修正相当）として
  リリースノート・ドキュメントに明記し、回帰テストで「Mode 0 分散 = シリアルと
  一致」を固定する。

### Mode 2: トレースカーネル

新ファイル `src/expec_trace.c`。対象: `expec_energy_flct` 相当（エネルギー・
対角量）、一体GF（`cisajs`）、二体GF（`cisajscktaltdc`）。構造は
**「演算子ごとに基底写像を 1 回前計算 → 所有全状態をストリーミング」**:

1. **写像前計算**: 演算子 Ô（例: c†ᵢσ cⱼσ）について、各基底状態 k に対する
   行き先 k′ と符号/位相 s_k を O(N) の配列として 1 回だけ構築する。
   **写像は演算子 1 個ずつ構築・使用・破棄**し（同時保持は 1 演算子分の
   O(N) のみ。キャッシュしない）、ペア数が多くてもメモリは増えない。
   ビット演算は「**汎用経路が呼ぶのと同一の要素関数**（`child_*` /
   `GC_child_*` 系）を k ごとに 1 回呼んで (k′, s_k) を記録する」形で
   再利用する — 符号・位相・順序の規約が構造的に汎用経路と一致する。
   要素関数のうち副作用（グローバル累積、`X->Large` の書き換え等）を持つ
   ものは実装時に列挙し、純粋な写像抽出アダプタを介して呼ぶ。
2. **状態ストリーミング**: `g_n = Σ_k conj(z_n[k′]) · s_k · z_n[k]` を
   所有状態 n について密ループで評価（メモリバンド幅律速）。
   汎用 expec コードが状態×要素ごとに払うテーブル参照・分岐コストを
   N/P 状態分だけ償却するのが Mode 1 に対する利点。
2b. **写像抽出アダプタの受け入れ基準**: ソース監査に加え、**「同一演算子の
   写像抽出を 2 回実行して結果が一致し、かつ `X`（Large/Phys の関連フィールド）
   が変化しない」ことを検査する単体テスト**を各モデルのゴールデンテストに
   含める（副作用の混入を実行時にも検出）。
3. **エネルギー系**: `<H>` は固有値をそのまま採用。対角量（ダブロン、num、Sz）
   は対角写像の自明なストリーミング。分散 `<H²>-<H>²` の検査は同じ写像機構で
   H の全項を適用して任意実行（既定 ON、従来出力との互換のため）。
4. **二体GF**: 合成順序・フェルミオン符号・中間状態の消滅（粒子数制約で
   0 になるケース）・同一添字の縮約規則は、**既存 `expec_cisajscktaltdc` の
   モデル別実装が呼ぶ要素関数の呼び出し列をそのまま写像抽出に使う**ことで
   規約ごと継承する（独自に演算子代数を再実装しない）。スピン組合せ・
   ペア数のループが外側に増えるだけで、内側の状態ストリーミングは共通。
5. **モデル別の段階的有効化**: カーネルはモデル（Hubbard / Spin / SpinGC /
   Kondo / 汎用スピン / spinless）ごとに、§6 のゴールデンテスト（非対角項・
   密度-密度対角項・同一添字・ゼロ結果演算子を汎用経路と突き合わせ）に
   合格したものだけ有効化する。未検証モデルは自動的に Mode 1 経路へ
   フォールバック（機能マトリクスを `expec_trace.c` に定数表として持つ）。
   初期対象は Hubbard と Spin/SpinGC。
6. **フォールバック**: NBodyG / AnomalousG など対象外の物理量・未検証モデルは
   その量/状態だけ Mode 1 の経路（ローカルモード + 既存 expec）で処理する。
   どの量がカーネル/フォールバックかは開始時に rank 0 が INFO 表示（§2）。
   **量ごとの所有表**（最小版、実装計画で細目化）:

   | 対象 | Mode 2 での書き手 |
   |---|---|
   | `all_energy`（=固有値）, `all_doublon`, `all_num_up/down`, `all_sz` | トレースカーネル |
   | `all_s2` | トレースカーネル（対象モデル）/ フォールバック（未検証モデル） |
   | 一体GFファイル（状態別・集約） | トレースカーネル（対象モデル）/ フォールバック |
   | 二体GFファイル | 同上 |
   | NBodyG / AnomalousG ファイル | 常にフォールバック |
   | stdout 進捗行 | ドライバ（集約後に rank 0） |

   各対象につき書き手は常に一意（カーネルが担当する量はフォールバックを
   呼ばない）。同一状態内での二重書き込み・部分上書きを構造的に排除する。
7. 出力は Mode 1 と同じ機構（状態別はローカル書き、集約はランク順連結）。

### phys.c の分岐

`phys()` の冒頭で `ExpecMode >= 1 && use_scalapack` なら
`phys_stateparallel()`（Mode 2 はその中でカーネル選択）へ委譲する。
Mode 0 では従来の `GetEigenVectorBlock` 経路のままとし、従来経路への変更は
**唯一の例外**を除いて行わない: その例外が §「Mode 1」記載の S²/Sz 統一
— 分散 Mode 0 の状態ループ内で、rank 0 に集約済みの `v0` に対して
`ExpecLocalEnter/Leave` で囲んだ `expec_totalspin` を追加実行し、
S²/Sz のゼロ埋めを廃止して表示形式をシリアル版に統一する。
状態パネルへの再分散は委譲直前に実行する（Mode 0 では行わない）。

## 4. エラー処理

- readdef 起動時検証（§2）で不整合を全て事前に弾く。
- `RedistBlockCyclicToStatePanel` はフェーズ2 と同じ集団同期パターン
  （malloc 失敗の Allreduce 同期、所有権整合ガード、失敗時は全ランク同時に -1）。
- `iExpecLocal` の set/reset は構造的に対にする。expec 中のエラーは
  ローカルモードを解除してから集団的に伝播（全ランク `MPI_Allreduce(MIN)` で
  失敗共有 → `exitMPI`）。
- パーシャルファイル連結は rank 0 のみが行い、成否は §3 のマニフェスト規則に
  従う（エラーは attempted=真 かつ open_error=真、または非空レコードの part が
  開けない場合のみ。ゼロ所有ランク・正当な空出力は正常）。連結・公開・削除は
  グローバル rc 成功時のみ。

## 5. 出力互換性

- 状態別ファイル（`zvo_cisajs_eigen%d.dat` 等）: ファイル単位で従来と同一内容。
- 集約形式（`green_output_format` 機能）: rank 0 がランク順（＝状態順）に
  パーシャルを連結し、従来と同一のファイルを生成する。
- `zvo_phys_*.dat`（サマリテーブル）と標準出力の `i=... Energy=...` 行:
  all_* 集約後に rank 0 が状態順で出力（従来と同一）。
- 従来（分散実行）との差分は「`<S²>`/`Sz` がゼロ埋めでなく計算されるように
  なり、標準出力がシリアル形式（S2 列あり）に統一される」こと。これは
  Mode 0/1/2 すべてに適用する意図的な挙動修正（§3 Mode 1 参照）で、
  リリースノートとドキュメントに明記する。
- 総和順序の変更により Mode 間の一致は丸め誤差の範囲（bit 一致ではない）。
  ユーザードキュメントに明記する。

## 6. テスト計画

- **モード等価性（主軸）**: 同一入力で `ExpecMode 0/1/2` の全出力
  （phys テーブル、状態別・集約 Green ファイル、標準出力サマリ行）を比較。
  エネルギーは一致、GF・S²・Sz は 1e-8（総和順序差の丸め）、標準出力の
  列構成はシリアル形式と同一であること。対象: Hubbard 鎖（一体・二体GF）と
  SpinGC Gamma≠0、および正準 Spin 模型 1 ケース（S²/Sz 統一の影響範囲を
  カバー）。np = 2/3/4 の複数構成（ゼロ所有状態ランクを含む構成も）。
- 状態パネル再分散の単体テスト（`elpa_redist_check` の姉妹版:
  `GetEigenVectorBlock` による列回収結果とパネル内容の全要素比較）。
- Mode 2 カーネル単体: ランダムベクトルに対して演算子写像の結果を
  汎用 expec（Mode 1 経路）と突き合わせ。
- 既定動作の回帰: `ExpecMode 0`（既定）で全既存テスト無変更 PASS。
- clavius 実機 + **ベンチマークゲート**: N=4900 全状態の一体+二体GF 実時間を
  Mode 0 / 1 / 2 で比較（有限温度ワークロードの代理）。目標: Mode 1 で ~P 倍、
  Mode 2 は Mode 1 以上。
- 集約出力の結合テスト: 複数ランク・非整除 N/P・ゼロ所有状態ランク構成で
  集約ファイルが Mode 0 と同一になること。パーシャル欠損（書き込み失敗の
  シミュレーション）で連結がエラー終了すること。
- Mode 0 分散の `<S²>`/`Sz` 修正の回帰テスト: 分散 Mode 0 の出力がシリアル
  実行と一致すること（従来のゼロ埋めに戻っていないこと）。あわせて
  **既存テストの棚卸し**: `fulldiag_elpa_hubbard_chain.sh` の「S2/Sz を計算
  しないため該当列を除外」という回避コメントと列選別を撤去し、S² 列込みの
  比較に強化する（同様の回避をしているテストがあれば同時に更新）。
- wrapperMPI ガード: expec 経路のソースにマトリクス外の MPI ラッパー呼び出しが
  現れたら失敗する grep ベースのチェック。
- ベンチマークは N=4900 に加え、可能なら 1 点だけ大きい N（例 L=10 Hubbard,
  N≈63504、対角化は GPU）でも Mode 0/1 の実時間を記録し、損益分岐と
  スケーリングの外挿根拠にする（Mode 2 の损益分岐点も報告する）。
- 手動検証プロトコル（`test/manual/elpa_gpu_check.md`）へのフェーズ3 項目追加は
  **3a の成果物**とする（Mode 1 だけでもユーザー可視の変更があるため）。

## 7. 検討した代替案（不採用）

- **真の PBLAS トレース形式（ブロックサイクリックのまま pzgemm で
  diag(Z†OZ)）**: 演算子は疎な基底置換なので密 BLAS3 の恩恵がなく、
  ブロックサイクリック上の置換適用は通信を伴い複雑になるだけ。状態パネル上なら
  演算子適用が通信ゼロになるため不採用。
- **サイト分割レイアウトへの載せ替え**（Lanczos/TPQ の MPI 並列 expec を再利用）:
  FullDiag は起動時に非分割モードを選んでおり（`iFlgScaLAPACK` ゲート）、
  `list_1` 等の分割簿記との整合コストが最も高い。不採用。
- **ラウンドロビン状態配分**: 負荷分散上の利点がなく（状態あたり仕事一様）、
  出力の状態順集約が複雑になるため、ブロック配分を採用。
